# 对话关联患者与诊疗阶段

## Context

医生端对话不再是纯聊天窗口，而是可以直接绑定患者和具体诊疗阶段。这样 AI 在读取上下文、保存报告、写入时间线、创建待办时，能落到正确的业务对象上。

**核心需求：** 会话支持绑定 `patient_id` 和 `timeline_id`，并在后续 agent 运行时自动透传。

------

## Architecture

```
医生端聊天页 →
选择/切换患者 →
选择该患者下的诊疗阶段 →
run agent 时携带 patient_id / timeline_id →
工具写入患者档案、时间线、报告、待办
```

数据库依赖：

- `conversation_record_t.patient_id`
- `conversation_record_t.patient_name`
- `conversation_record_t.linked_timeline_id`
- `conversation_record_t.linked_timeline_name`

------

## Implementation Steps

### Phase 1: 会话存储患者和时间线上下文

后端 `/opt/backend/apps/conversation_management_app.py` 提供：

- `PUT /conversation/link_patient`
- `PUT /conversation/link_timeline`

### Phase 2: 聊天页维护本地绑定状态

前端 `/opt/frontend/app/[locale]/chat/internal/chatInterface.tsx` 负责：

- 当前会话切换时同步已绑定患者/时间线
- 医生端展示患者选择器和时间线选择器
- 患者变化时清空旧时间线，避免串档

### Phase 3: Agent 运行自动带业务上下文

医生端发起聊天时，`runAgentParams` 自动附带：

- `portal_type`
- `patient_id`
- `timeline_id`

这样后续 MCP 工具和智能体逻辑不需要再次询问保存目标。

------

## Critical Files

| File | Role |
