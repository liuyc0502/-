# 端口智能体分配

## Context

医生端和患者端并不是每次手动选择 agent，而是由后台预先分配 portal 主智能体和可调用的子智能体集合。当前系统已经有独立的端口分配页。

**核心需求：** 为医生端、患者端分别配置默认主智能体及可挂载能力。

------

## Architecture

```
管理端分配页 →
选择 doctor / patient 端口 →
查看该端口主智能体 →
拖拽或添加可用子智能体 →
保存分配结果 →
聊天页自动加载 portal main agent
```

核心表：

- `ag_portal_agent_assignment_t`

------

## Implementation Steps

### Phase 1: 分配接口

后端 `/opt/backend/apps/portal_agent_assignment_app.py` 提供：

- 获取端口主智能体
- 获取端口子智能体列表
- 分配 agent
- 移除 agent
- 整体重设 agent 列表

### Phase 2: 管理端分配页

前端 `/opt/frontend/app/[locale]/admin/components/AgentAssignment.tsx` 提供：

- 医生端/患者端切换
- 已分配列表与候选池
- 分类筛选
- 拖拽分配与移除

### Phase 3: 对聊天页的影响

前端聊天页会基于端口类型自动加载：

- doctor portal 主智能体
- patient portal 主智能体

这样端口差异不靠前端写死，而靠后台分配控制。
