# 对话状态 + 标签 + 摘要 + 归档

## Context

医生端对话除了聊天内容，还需要做病例流转管理。当前系统已经支持对话状态、标签、摘要和归档，这使一段 AI 对话可以被纳入患者管理流程。

**核心需求：** 会话支持从“聊天记录”升级为“可管理病例资产”。

------

## Architecture

```
会话列表 / 会话详情 →
设置状态 / 标签 / 摘要 →
单条或批量归档 →
可按患者查看关联对话
```

数据库依赖：

- `conversation_record_t.conversation_status`
- `conversation_record_t.tags`
- `conversation_record_t.summary`
- `conversation_record_t.archived_at`
- `conversation_record_t.archived_to_timeline`

------

## Implementation Steps

### Phase 1: 会话元数据接口

后端 `/opt/backend/apps/conversation_management_app.py` 提供：

- `PUT /conversation/status`
- `PUT /conversation/tags`
- `PUT /conversation/summary`
- `POST /conversation/archive`
- `POST /conversation/batch_archive`
- `GET /conversation/patient/{patient_id}/conversations`

### Phase 2: 前端会话管理封装

前端 `/opt/frontend/services/conversationService.ts` 封装：

- `updateStatus`
- `updateTags`
- `updateSummary`
- `archive`
- `batchArchive`
- `getByPatientId`

### Phase 3: 医生端工作流

这些能力主要服务于：

- 标记“待跟进 / 疑难病例 / 已完成”
- 给会话打业务标签
- 给长对话补摘要
- 归档后回到患者档案或时间线复盘

------
