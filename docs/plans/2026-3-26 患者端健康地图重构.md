# 患者端健康地图与医生端知识图谱

## Context

系统中有两个相关但独立的功能：

- **医生端知识图谱**：医生输入查询 → 从 ES 知识库检索文档 → LLM 抽取实体关系 → 生成交互式网络图谱
- **患者端健康地图**：自动根据患者 timeline 数据构建健康旅程可视化

两者共享后端 API 命名空间（`/api/knowledge-graph/`），但在算法、数据结构和前端展示上完全独立。

## 一、医生端知识图谱

### 功能说明

医生输入一个医学查询（如某种疾病、病理特征、指标组合），系统从知识库里检索文档，用 LLM 实时抽取实体和关系，生成一张结构化知识图谱。可以选择叠加某个患者的时间线，查看该患者在图谱上的位置、预测演变路径、检测轨迹异常。

### 数据流

```
医生输入 query
  → POST /knowledge-graph/generate
  → _search_documents(): ES 检索知识库文档
  → KnowledgeGraphService.generate_subgraph(): LLM 抽实体和关系
  → 生成 KnowledgeGraphData { nodes[], edges[], confidence }
  → 可选: _enrich_with_trajectory()
    → TrajectoryService.map_patient_trajectory(): 患者时间线映射到图节点
    → TrajectoryService.predict_paths(): 预测演变路径 (PPS)
    → TrajectoryService.detect_anomalies(): 异常路径检测 (APD)
  → 缓存到 knowledge_graph_cache_t
  → 前端 GraphViewer (ReactFlow) 渲染网络图
```

### 数据结构：KnowledgeGraphData

```
{
  card_type: "knowledge_graph",
  query: string,
  confidence: 0.0-1.0,           // 整图置信度
  nodes: KnowledgeGraphNode[],    // 实体节点
  edges: KnowledgeGraphEdge[],    // 关系边
  patient_position?: {            // 可选：患者轨迹
    current_nodes: string[],
    visit_history: [{ date, node_ids }]
  },
  predictions?: PredictionPath[],  // 可选：演变预测
  anomalies?: TrajectoryAnomaly[], // 可选：异常检测
}
```

节点类型（7种）：Disease、PathologicalFeature、Biomarker、Treatment、TestMethod、Organ、ClinicalStage

关系类型（7种）：indicates、causes、differentiates_from、progresses_to、treats、detected_by、associated_with

### 核心算法

**DKSG（动态知识子图生成）** — `KnowledgeGraphService.generate_subgraph()`

1. 整理 ES 检索到的文档（最多 10 篇，每篇截取 2000 字）
2. 调 LLM 使用 `ENTITY_RELATION_EXTRACTION_PROMPT` 抽取实体和关系
3. 校验节点/边类型合法性、引用完整性
4. 计算整图置信度（70% 边权重均值 + 30% 规模因子）

**PPS（预测路径评分）** — `TrajectoryService.predict_paths()`

基于患者当前图谱位置 + 图结构 + 历史轨迹，LLM 预测最多 5 条可能的演变路径，每条含概率、推理依据和时间范围。

**APD（异常路径检测）** — `TrajectoryService.detect_anomalies()`

从图谱中提取典型路径（高权重 `progresses_to` 边），与患者实际轨迹对比，LLM 评估偏离程度（anomaly_score ≥ 0.3 才报告）。

## 二、患者端健康地图

### 功能说明

患者进入健康地图页面，系统自动从患者的 timeline 数据库记录构建健康旅程可视化。展示：当前阶段、诊疗历程、检查项目、治疗方案、预测和提醒。

### 数据流

```
患者端进入健康地图
  → HealthMapService.generate_health_map(patient_id)
  → get_patient_by_id(): 获取患者基本信息
  → get_patient_timeline(): 获取所有时间线阶段
  → get_timeline_detail(): 获取每个阶段的详情、指标、图片
  → 直接构建 HealthMapEvent[] (来自数据库字段，不经 ES 和 LLM)
  → 可选: LLM 生成摘要/预测/提醒 (失败不影响核心数据)
  → 缓存到 knowledge_graph_cache_t
  → 前端 JourneyPathSVG (SVG) 渲染线性旅程
```

### 数据结构：PatientHealthMapData

```
{
  card_type: "patient_health_map",
  patient_name: string,
  primary_diagnosis: string,
  current_stage: string,
  journey_progress: 0.0-1.0,
  events: HealthMapEvent[],            // 核心：来自 timeline 数据库
  predictions: HealthMapPrediction[],  // 可选 LLM 增强
  alerts: HealthMapAlert[],            // 可选 LLM + 规则
  overall_summary: string,             // 可选 LLM 增强
}
```

### HealthMapEvent（一个诊疗事件）

```
{
  event_id: string,          // "evt_{timeline_id}"
  date: string,              // stage_date
  stage_type: string,        // 初诊/检查/确诊/治疗/随访
  title: string,             // stage_title
  diagnosis: string | null,
  status: completed/current/pending,
  is_current: boolean,
  summary: string | null,    // 来自 patient_summary
  suggestions: string[],     // 来自 patient_suggestions
  medications: [{name, dosage}],
  metrics: [{name, value, unit, trend, status}],
  has_reports: boolean,      // 是否有影像/图片
}
```

### 字段来源映射

| HealthMapEvent 字段 | 数据库来源 |
| :-- | :-- |
| date | `patient_timeline_t.stage_date` |
| stage_type | `patient_timeline_t.stage_type` |
| title | `patient_timeline_t.stage_title` |
| diagnosis | `patient_timeline_t.diagnosis` |
| status | `patient_timeline_t.status` |
| summary | `patient_timeline_detail_t.patient_summary` |
| suggestions | `patient_timeline_detail_t.patient_suggestions` |
| medications | `patient_timeline_detail_t.medications` |
| metrics | `patient_metrics_t.*` |
| has_reports | `patient_medical_image_t` 是否存在记录 |

### 规则化提醒（无需 LLM）

HealthMapService 内置了基于规则的提醒逻辑：

1. 最后一次就诊超过 6 个月 → 提醒预约复查
2. 当前阶段有异常指标（status=error/warning 且 trend=up）→ 提醒关注

这些规则化提醒不依赖 LLM，即使 LLM 不可用也会生效。

| File | Role |
| :-- | :-- |
| `backend/services/health_map_service.py` | 核心：直接从 timeline 数据库构建健康地图 |
| `backend/prompts/health_map_prompts.py` | 3 个患者友好 LLM prompt（摘要/预测/提醒） |

## 三、共享基础设施

### API 控制器

`backend/apps/knowledge_graph_app.py` 同时服务两端：

- `POST /generate` — 医生端：query + 可选 patient_id → KnowledgeGraphService
- `POST /patient-map/generate` — 患者端：自动从 timeline → HealthMapService
- `POST /predict` — 医生端：对已有图谱重新跑 PPS/APD
- `GET /history` — 两端共用，通过 `portal_type` 参数过滤
- `GET /history/{cache_id}` — 两端共用，通过 `card_type` 自动返回对应格式

### 缓存

两端共用 `knowledge_graph_cache_t` 表，通过 `subgraph_json._meta` 中的 `portal_type`、`patient_id`、`source` 做逻辑隔离：

- 医生端：`source = "doctor_explorer"`
- 患者端：`source = "patient_health_map_v2"`

history 端点检测 `card_type`：`"patient_health_map"` → 返回 `health_map` key，`"knowledge_graph"` → 返回 `knowledge_graph` key。

### 前端类型

- `frontend/types/knowledgeGraph.ts` — 医生端知识图谱类型（KnowledgeGraphData、KnowledgeGraphNode、KnowledgeGraphEdge 等）
- `frontend/types/healthMap.ts` — 患者端健康地图类型（PatientHealthMapData、HealthMapEvent 等）

### 前端 API 端点配置

`frontend/services/api.ts` 中的 `knowledgeGraph` 命名空间：

```
knowledgeGraph: {
  generate:            "/api/knowledge-graph/generate",            // 医生端
  patientMapGenerate:  "/api/knowledge-graph/patient-map/generate", // 患者端
  predict:             "/api/knowledge-graph/predict",             // 医生端
  history:             "/api/knowledge-graph/history",             // 共用
  historyDetail:       "/api/knowledge-graph/history/{cacheId}",   // 共用
}
```
