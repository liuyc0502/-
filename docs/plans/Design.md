# 安语 AI 病理知识问答智能体 — 功能总览与创新规划

> 日期: 2026-03-15

---

## 一、产品定位

一句话定位：**一个面向病理医生的病理知识问答与报告辅助智能体。**

核心目标不是做重型 HIS 平台，也不是直接替代医生诊断，而是聚焦三件事：

1. **把病理知识问准、答准、答得有依据**
2. **把病理报告看懂、拆开、解释清楚**
3. **把病例、知识和问答过程沉淀为可复用资产**

---

## 二、现有功能（已实现）

### 整体架构

当前已落地三端入口：**医生端** · **患者端** · **管理端**

三端共用聊天框架、后端服务、知识库能力与文件处理能力，其中医生端是当前最完整、最贴近病理知识问答场景的主入口。

---

### 医生端

#### 核心页面


| 页面    | 功能                                  |
| ----- | ----------------------------------- |
| 患者列表  | 搜索、筛选、创建患者，查看患者基本信息                 |
| 患者详情  | 查看患者概览、诊疗时间线、康复计划、待办事项              |
| 诊疗时间线 | 按时间轴展示就诊记录、检验报告、影像报告、病理发现、附件与指标变化   |
| 病例库   | 搜索/创建/收藏病例，查看症状、检查结果、病理发现与处理过程      |
| 知识库   | 访问医学知识资源，支撑病理相关知识问答                 |
| 对话界面  | 与 AI 助手对话，可关联患者和时间线，进行病例讨论与知识问答     |


#### 对话增强功能


| 功能    | 描述                              |
| ----- | ------------------------------- |
| 关联患者  | 对话可绑定患者，AI 自动获取患者上下文            |
| 关联时间线 | 对话可绑定诊疗阶段，保存的数据自动归入该阶段          |
| 对话状态  | 标记对话为进行中/待跟进/疑难病例/已完成/已归档       |
| 对话标签  | 自定义标签，便于分类检索                    |
| 对话摘要  | 编辑和保存对话摘要                       |
| 快捷指令  | `/` 触发常用指令面板（chatCommandPicker） |
| 对话模板  | 预设模板快速发起常见任务                    |


#### AI 智能体工具集（已接入 MCP 工具）


| 类别    | 工具数 | 主要能力                          |
| ----- | --- | ----------------------------- |
| 患者管理  | 5   | 创建、更新、删除、搜索患者，重复检测            |
| 时间线管理 | 9   | 创建事件、保存详情、上传图片/附件、保存病理发现与指标数据 |
| 报告管理  | 8   | 保存/查询/删除检验报告、影像报告及相关明细        |
| 病例库管理 | 10  | 创建/更新病例、保存症状和检查结果、收藏管理        |
| 待办事项  | 3   | 创建/更新/删除患者待办任务                |
| 病例检索  | 5   | 按条件搜索相似病例、获取病例详情              |

### 后端服务


| 服务          | 描述                                     |
| ----------- | -------------------------------------- |
| AI Agent 框架 | 基于 Nexent SDK，支持多步推理、工具调用、流式输出         |
| 知识库检索       | 支持本地知识库检索，为回答提供知识来源                   |
| 文件管理        | MinIO 对象存储，支持图片/PDF/文档上传下载             |
| OCR 服务      | PaddleOCR，支持从图片中提取文字                   |
| 对话管理        | 对话历史、多轮上下文、患者关联                        |
| 多租户         | 租户隔离，支持多机构部署                           |
| 数据库         | PostgreSQL（Supabase），ORM 基于 SQLAlchemy |

## 三、创新功能（已实现）

### 医生端创新（3 个）


| #   | 创新点               | 描述                                                                                               | 设计文档                                                          |
| --- | -------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1   | ⭐ 病理报告结构化解读 + 质控(待验证) | 上传报告后 AI 自动拆为”核心诊断、关键描述、术语解释、临床意义、待确认点”五板块，同时质控检查缺失字段（切缘、脉管侵犯、TNM 等），红黄绿标记 | [设计文档](2026-3-15%20Report_Interpretation_QC.md) |
| 2   | ⭐ 病理知识溯源链         | AI 回答时展示完整推理过程：引用哪条知识→推出什么结论→为什么排除其他可能→最终置信度，可视化 Chain-of-Thought                          |                                                                   |
| 3   | ⭐ 多智能体辩论会诊       | 多个专科 Agent 并行分析 → 多轮辩论 → 医生介入控制（继续辩论/附加指导/形成结论）→ 共识报告，实现从”单专家”到”专家团队”的会诊工作流 | [设计文档](2026-3-20%20Multi-Agent%20Debate%20Consultation.md) |
### 患者端创新（2 个）


| #   | 创新点            | 描述                                                                                          | 设计文档 |
| --- | ----------------- | --------------------------------------------------------------------------------------------- | -------- |
| 5   | ⭐ 报告通俗解读(待验证) | 同一份报告用大白话解释，标注严重程度（绿/黄/红），给出下一步建议，和医生端专业解读形成对比                                 |          |
| 6   | ⭐ 症状自报 + 智能导诊(待验证) | AI 引导式提问（部位→特征→时长→伴随症状），生成结构化症状摘要卡片 + 就诊科室建议，帮患者”整理好信息再去看医生”              |          |

### 贯穿能力（通过 System Prompt 实现，不需额外开发）


| #   | 能力           | 描述                                                         |
| --- | -------------- | ------------------------------------------------------------ |
| A   | 证据可追溯问答 | 每次回答附带知识来源引用，说明依据                           |
| B   | 结构化追问模式 | 信息不足时先追问器官部位、标本类型、形态特征、IHC 结果再分析 |
| C   | 鉴别诊断辅助   | 给出鉴别诊断思路与排除路径，不替代医生下结论                 |
| D   | IHC 染色建议   | 信息不足时推荐下一步免疫组化标记及用途                       |
